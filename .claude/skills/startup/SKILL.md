# 開工接續助手

新對話開始時，幫使用者快速進入「上次做到哪」的脈絡，避免從零開始解釋。

## 核心原則

1. **不主動 git pull / merge**（避免覆蓋本地未 commit 變動，只提醒）
2. **只讀不寫**：不改工作筆記（那是 `/收工` 的事）
3. **若沒有工作筆記就回報 + 詢問**，不亂建檔
4. **跟 `/收工` 是對偶關係**：收工寫進去、開工讀出來

## 開工 SOP（依序執行）

### 步驟 1：確認工作目錄
- 在 repo 根目錄（有 `.git`、`CLAUDE.md`）
- 記下目前分支：`git branch --show-current`

### 步驟 2：讀 `工作筆記.md`
找不到 → 提醒「建議先用懶人包 #07 初始化」，仍繼續做 git 檢查。

### 步驟 3：摘要「上次做到哪」
精簡讀出（不要全文倒出來）：
- 「⏯️ 上次做到哪」
- 「➡️ 下一步」
- 「🕳️ 踩坑筆記」最近一筆（只在跟下一步直接相關時提）

### 步驟 4：檢查本地 git 狀態
```bash
git status --short
```
- clean → 「本地工作區乾淨」
- 有未 commit 變動 → 列出，問「要繼續還是放棄？」

### 步驟 5：檢查遠端
```bash
git fetch origin main "$(git branch --show-current)" 2>/dev/null
git rev-list HEAD..origin/main --count          # main 上有、本分支還沒有的 commit
git rev-list HEAD..origin/"$(git branch --show-current)" --count 2>/dev/null
```
- > 0 → 提醒「遠端有 N 個新 commit，要合併進來嗎？」**不主動做**
- = 0 → 「本地是最新狀態」

### 步驟 6：報告 + 建議下一步
```
📂 專案：teaching-tools（分支：<branch>）
📘 上次做到哪：<1-2 句>
🔧 本地 git：<clean / 有 N 個未 commit 變動>
🌐 遠端：<最新 / 落後 N commits>
➡️ 建議下一步：
   1. <工作筆記「下一步」第 1 項>
   2. <可選>

要從哪個方向開始？
```
等使用者選方向，不要自己擅自繼續。

## 不該做的事
- ❌ 主動 `git pull` / merge
- ❌ 修改工作筆記
- ❌ 沒有工作筆記時硬建一個（先問）
- ❌ 把工作筆記全文倒出來
